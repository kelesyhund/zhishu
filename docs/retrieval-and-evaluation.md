# 检索与质量评测

## 文档解析与切片

系统按文件类型选择 TXT、Markdown、PDF 或 DOCX 解析器。切片记录正文、标题路径、页码、位置、Token 数、内容哈希和解析器版本，用于引用、去重、变更判断与可复现评测。

结构化切片遵循以下原则：

- 标题感知，尽量不跨越章节边界。
- 表格、代码块和列表尽量保持为完整语义单元。
- 父子切片以较小子块召回，以父章节补充生成上下文。
- 重处理成功后原子替换；失败保留原有可用切片和签名。

## 混合检索链路

```text
Query
  ├─► BM25 关键词召回 ─┐
  └─► Embedding 召回 ──┼─► RRF/Weighted Fusion
                        └─► Cross-Encoder Reranker（可选）
                              ► 上下文预算 ► Answer + Citations
```

- BM25 对产品编号、错误码、命令和精确参数更敏感。
- Embedding 用于语义改写和近义表达。
- RRF 按排名而不是原始分数融合异构检索结果。
- Reranker 对候选片段进行查询相关性精排；超时、模型不可用或并发受限时降级到融合结果。
- Top-K、阈值、候选数量和上下文长度都有上限，并可通过检索调试信息定位召回或排序问题。

文档只有在向量签名与知识库当前 Embedding 空间兼容时才参与向量检索。数据库检索实现见 [向量存储](vector-storage.md)。

## 评测数据治理

评测集面向企业技术文档和故障排查，覆盖精确关键词、语义改写、多文档问题、表格、版本差异与无答案问题。每个问题应包含：

- 稳定 ID、问题类型和标准答案要点。
- 一个或多个相关切片及 0/1/2 相关度。
- 数据来源、审核状态和修改记录。
- 使用的语料版本、配置快照与随机种子。

开发集用于调参，冻结测试集只用于最终比较。冻结时记录清单和 SHA256；任何内容变化都产生新版本，避免反复查看测试结果造成数据污染。自动生成样本只能标记为候选，不能替代人工审核。

## 指标

检索层记录 Recall@K、MRR、NDCG@K 和每条查询的候选排名。答案层记录 Citation Precision、Citation Recall、Faithfulness、No-answer Accuracy、首 Token 延迟和总响应时间。

每份正式报告必须包含：

1. 分子、分母和逐题结果。
2. 语料与测试集哈希。
3. 检索、Embedding、Reranker 和生成模型配置快照。
4. 硬件、并发、超时和降级次数。
5. 基线与候选方案的相同条件对比。

仓库中的自动草稿或合成样本不能表述为真实用户准确率。当前公开数据仍需完成不少于 100 题的人工复核与冻结，才能形成对外可引用的质量结论。

## 降级与失败解释

Reranker 故障不阻断主检索链路，系统记录降级原因、耗时和候选数。无证据或证据低于阈值时优先拒答，而不是让模型补全事实。若新方案没有超过最佳基线，应保留真实结果并按问题类型分析解析、召回、排序或标注环节。
