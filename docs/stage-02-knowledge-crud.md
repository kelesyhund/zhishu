# 第二阶段设计：知识库详情、修改、搜索与分页

## 1. 阶段目标

在不引入 Redis、Celery、pgvector 和新数据库字段的前提下，补齐知识库管理能力：

- 查询当前用户的知识库列表，并支持关键字搜索和分页。
- 查询当前用户的单个知识库详情。
- 修改当前用户知识库的名称和描述。
- 保持登录、创建、删除、文档上传、检索和流式问答功能兼容。
- 为新增的正常路径、校验路径和越权路径补充后端自动化测试。

## 2. 现状审计

### 已有能力

- `GET /api/knowledge-bases/`：返回当前用户的全部知识库数组。
- `POST /api/knowledge-bases/`：创建知识库。
- `DELETE /api/knowledge-bases/{id}/`：删除自己的知识库。
- 前端列表页支持创建、查看列表和删除。
- 详情页支持文档上传、文档列表、流式问答和引用展示。
- DRF TokenAuthentication 和默认 IsAuthenticated 已启用。

### 基线验证

- 后端：2 个现有测试通过。
- 前端：受限执行环境阻止 `esbuild` 创建子进程，基线构建报 `spawn EPERM`；最终验证需在允许子进程的环境重跑。
- 当前工作目录没有 Git 元数据，无法使用 `git diff`；实施时使用精确补丁并逐文件复查。

### 当前缺口

- 单个知识库路由只有 DELETE，没有 GET 和 PATCH。
- 名称只依赖模型字段校验，纯空格名称可通过。
- 列表没有搜索、分页和统一分页元数据。
- 详情页没有展示知识库名称与描述。
- 前端创建和编辑没有共用的表单流程。

## 3. 范围边界

### 本阶段包含

1. 知识库详情 GET。
2. 知识库部分更新 PATCH。
3. 列表名称/描述模糊搜索。
4. 服务端分页和前端分页器。
5. 创建/编辑共用弹窗。
6. 名称去除首尾空格与空值校验。
7. 详情、修改、搜索、分页和越权测试。

### 本阶段不包含

- 注册、JWT、工作空间和 RBAC。
- 知识库名称唯一约束。
- 文档删除、重试、切片预览。
- 异步任务和向量数据库。
- 历史对话界面和 Agent 工具调用。

## 4. API 契约

### 4.1 列表、搜索与分页

```http
GET /api/knowledge-bases/?keyword=python&page=1&page_size=12
Authorization: Token <token>
```

规则：

- `keyword` 可省略，对名称和描述执行不区分大小写的包含查询。
- `page` 默认 1；无效值回退到可用页。
- `page_size` 默认 12，最小 1，最大 100；非数字回退到 12。
- 只返回 `owner=request.user` 的数据。

响应：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "items": [],
    "total": 0,
    "page": 1,
    "page_size": 12,
    "total_pages": 0
  }
}
```

### 4.2 查询详情

```http
GET /api/knowledge-bases/{id}/
```

- 属于当前用户：返回知识库序列化数据。
- 不存在或属于其他用户：统一返回 HTTP 404，避免泄露资源是否存在。

### 4.3 修改详情

```http
PATCH /api/knowledge-bases/{id}/
Content-Type: application/json

{
  "name": "新名称",
  "description": "新描述"
}
```

- 使用 `partial=True`，允许只提交一个字段。
- `name` 自动去除首尾空格，去除后不能为空，长度继续由模型的 100 字符限制校验。
- `description` 自动去除首尾空格。
- 不存在或属于其他用户：HTTP 404。
- 成功：HTTP 200，返回修改后的完整知识库数据。

## 5. 前端交互与状态

### 列表页

- 标题区域增加搜索输入框和搜索按钮；回车触发搜索，清空输入后恢复全部数据。
- 列表响应保存为 `items/total/page/pageSize/totalPages`。
- 切换页码后重新请求服务端数据。
- 创建成功后回到第一页并重新加载，保证总数和排序正确。
- 编辑按钮使用 `.stop`，避免点击编辑时进入详情页。
- 删除当前页最后一条数据后，如果不是第一页，则退回上一页再加载。

### 创建/编辑弹窗

- 使用同一套 `form` 和保存函数，通过 `dialogMode` 区分创建与编辑。
- 打开创建弹窗时清空表单；打开编辑弹窗时复制卡片现有数据。
- 保存过程中按钮显示 loading，避免重复提交。
- 请求失败时保留弹窗和用户输入。

### 详情页

- 页面进入时并行加载知识库详情和文档列表。
- 标题显示知识库名称，副标题优先显示描述。
- 详情加载失败不阻塞原有文档列表错误处理，错误信息明确展示。

## 8. 设计自审结论

- **兼容性：** 列表响应由数组升级为分页对象，属于本阶段唯一有意修改的前端接口契约；仓库内调用方同步修改。其他接口保持原路径和响应外壳。
- **数据安全：** GET、PATCH、DELETE 均使用 `pk + owner` 查询，越权统一表现为 404。
- **数据库：** 不增加字段与约束，不需要迁移；名称唯一性留给后续产品决策。
- **性能：** 分页限制最大 100 条，避免一次返回全部记录；本阶段数据规模下文档数量统计的现有实现可接受。
- **复杂度：** 使用 Django 内置 Paginator 和现有 APIView，不引入新的分页框架配置，便于学习当前调用链。
- **回归控制：** 先保持现有测试通过，再增加新测试；详情页仅增加信息加载，不改变上传和问答函数。
