# 第十二阶段：知枢品牌与前端体验改造

## 1. 阶段目标

将项目从开发期名称 `Knowledge Chat` 升级为可展示的企业知识产品“知枢”，形成统一、克制的蓝白视觉体系，同时保持知识库、文档处理、模型配置、会话、Agent 与应用发布等既有业务功能兼容。

产品定位：**知枢｜企业知识中枢**。

品牌主张：**让散落的企业知识，成为可靠的生产力。**

## 2. 素材审计与使用边界

用户已确认所提供素材可以直接用于项目。素材以蓝天、山景、城市和交通场景为主，适合作为色彩与空间感来源。本阶段从中选择城市滨水素材作为登录页主视觉背景，以蓝色渐变遮罩保证标题和功能说明的可读性；其他图片暂不堆叠进业务页面，避免削弱企业工具的克制感。

选中素材复制为 `frontend/src/assets/zhishu-city-waterfront.jpg`，随前端构建产物发布，不依赖桌面原始路径。品牌图形继续使用 CSS 组件自行构建。

## 3. 视觉规范

- 主色：`#2563EB`，用于主要操作、选中态和品牌识别。
- 深色：`#0F2A52`，用于标题与重要信息。
- 背景：`#F4F8FF`，搭配白色内容容器。
- 边框：`#DCE7F6`，弱化分割线，提高页面通透感。
- 成功、警告和危险状态继续保留语义色，不用主色替代业务状态。
- 卡片、输入框、按钮、对话框和抽屉采用一致的圆角与阴影层级。
- 字体优先使用系统中文无衬线字体，减少额外字体下载和首屏阻塞。

## 4. 信息架构

新增统一 `AppShell`，将主要工作区收敛为三个一级入口：

1. 知识空间：知识库创建、检索、文档管理和问答。
2. AI 应用：把知识能力配置、发布并提供给第三方使用。
3. 模型服务：管理 Chat/Embedding 模型配置与连通性。

桌面端使用固定左侧导航，移动端转换为顶部导航；页面标题、说明和操作区由同一外壳管理，避免每个页面重复实现头部与退出逻辑。

## 5. 核心组件

### BrandLogo

`frontend/src/components/BrandLogo.vue` 提供完整和紧凑两种品牌形态。图形表达知识节点汇聚到中心枢纽；文字统一为“知枢 / KNOWLEDGE HUB”。组件不依赖位图资源，可在侧栏、登录页和公开问答页复用。

### AppShell

`frontend/src/components/AppShell.vue` 负责：

- 一级导航与当前路由高亮；
- 工作空间与产品能力提示；
- 当前用户展示和退出登录；
- 页面 eyebrow、标题、说明与操作插槽；
- 桌面/移动响应式布局。

业务页面仍负责自己的数据和事件，外壳不读取知识库、模型或应用数据，避免把展示组件变成新的全局业务状态中心。

## 6. 页面改造

- 登录页：使用左右分栏，左侧叠加已授权城市滨水主视觉并解释产品价值和可信检索能力，右侧保留原认证表单。
- 知识库列表：增加总知识库、可见文档、就绪知识库和检索模式概览；卡片突出名称、说明、文档数量和进入入口。
- 知识库详情：强化当前知识库身份、在线状态、问答欢迎区和输入操作，不改变文档、会话、检索与 SSE 逻辑。
- 模型服务：使用统一外壳和安全状态摘要，保留 Chat/Embedding 分栏、CRUD 和连通性测试。
- AI 应用列表：从普通表格调整为更适合产品浏览的应用卡片，同时保留创建、编辑、预览、停用和删除行为。
- 应用编辑与发布概览：统一为构建工作台和发布控制台视觉；原版本、安全、密钥和日志能力保持不变。
- 公开问答页：增加知枢品牌、应用身份和可信知识服务说明，不改变匿名访问与流式问答协议。

## 7. 兼容性与非范围

本阶段没有修改后端 Model、Migration、API 契约、认证协议、SSE 数据格式或数据库数据。没有大规模重构业务状态，也没有引入新的 UI 框架、图片 CDN 或分析服务。

所有已有事件处理和 API 调用保留在原页面，只调整组件结构、品牌文案和样式；这样可以将视觉改造的回归面限制在前端展示层。

## 8. 响应式与可用性

- 宽屏显示固定侧栏和完整页面说明。
- 中等宽度收紧内容间距与卡片列数。
- 手机宽度将侧栏变为顶部导航，知识库详情恢复单列布局。
- 主操作使用高对比度蓝色；危险操作继续使用危险语义。
- 加载、空状态、错误状态和禁用状态沿用 Element Plus 可访问组件。
- API Key 仍只在密码输入框短暂存在，没有因视觉改造加入浏览器持久化。

## 9. 设计自审

- 品牌一致性：登录、后台、详情和公开页均统一为“知枢”。
- 导航一致性：核心后台页面均复用同一外壳。
- 功能边界：外壳只处理导航和认证退出，不侵入业务状态。
- 素材风险：用户已确认素材授权；仅打包实际采用的一张图片，并使用语义化文件名管理。
- 新手可维护性：组件数量控制在品牌组件和页面外壳两个公共抽象，没有建立多余设计系统工程。
- 回归风险：页面模板改动较多，但 TypeScript 类型检查覆盖了组件属性、事件和导入关系；仍需执行真实浏览器逐页视觉验收。

## 10. 实施与验证记录

- `npm run type-check`：通过。
- 后端健康接口 `GET /api/health/`：返回 HTTP 200，证明既有后端仍在运行。
- 登录页首屏实机检查：修复问答预览卡负下边距造成的底部裁切；在当前桌面窗口中品牌、文案、能力卡和问答预览均完整可见。
- 登录故障复查：500 由本地 8000 端口未启动、Vite 代理无法连接后端导致；迁移无缺失，启动 Django 后 `/api/login/` 返回 200，浏览器使用演示账号成功进入知识空间。前端同时补充网络、超时和无安全错误正文的 5xx 友好提示。
- `npm run build`：TypeScript 阶段通过，但当前受控 Windows 环境禁止 Vite/esbuild 创建子进程，报 `spawn EPERM`，尚不能在该环境内把生产打包标记为通过。
- Vite 使用原生配置加载可以监听 `127.0.0.1:5173`，但浏览器请求触发客户端模块转换时仍被同一 `spawn EPERM` 拦截；因此仅能确认 HTML 入口返回 200，不能将该结果当作页面功能通过。
- 自动化截图：Edge Crashpad 在受控环境内被拒绝访问，未把未执行的视觉点击描述为通过。
- 待补验：启动前端后逐页检查登录、知识空间、知识库详情、模型服务、AI 应用、应用编辑/发布和公开问答页，并在普通本机 PowerShell 中再次执行生产构建。

## 11. 已知限制

1. 当前图标和品牌字标为代码生成的轻量方案，尚未经过正式商标检索与专业品牌注册。
2. 当前只在登录页使用一张已授权素材，其余页面仍以产品信息和操作效率为主。
3. 部分业务页面信息密度较高，本阶段未进行大规模交互重构。
4. 浏览器视觉验收需要在可控制浏览器或由用户按清单完成后才能最终关闭。
